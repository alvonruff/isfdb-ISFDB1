Merging Awards

Some notes about making sure the awards files are in sync with the bibliographic files: Merging with the awards database consists of X parts:
  1. Generating fiction data from the awards data.
  2. Merging new awards tags into records which already exist in the fiction database.
  3. Finding awards records have been previously merged, but show up as different due to some lexical reason.
  4. Merging in any new data.
Details:
  1. Do a fresh database build to insure that the most up-to-date version of the compiled files exist. The merging tools use the compiled versions of the files.

  2. Enter the source base at dbase.compiled, and run: 
    	../tools/ccawards -m
    This will generate the following files, all derived from the awards database: ANTHOLOGIES.aw, COLLECTIONS.aw, NOVELS.aw, and SHORTFICTION.aw. You will see these four files in the dbase.compiled directory. This tools uses the TA field in the award records to figure out whether the record refers to a novel, anthology, etc.

  3. Pick one of the files. As an example, we'll pick NOVELS. Concatenate the current NOVELS file with the awards version using: 
       cat ../dbase.ascii/NOVELS NOVELS.aw > OUT
    This will create a file that consists of all current novel entries, plus those we generated from the awards database.

  4. Now merge the file. Since the award data has bogus year information (when it comes to publication dates), use the -n option: 
       	../bin/merge -n OUT > OUT2
    This merges all records with the same title and author into a single record. More importantly, it merges the awards tags into any already existing records. At this point, the new file consists of the old version of the file (with any new award tags merged in), concatenated with possibly new records at the end of the file.

  5. Find the last title in the old NOVELS file. Split OUT2 into two files: OUT.1 and OUT.2. In OUT.1, remove all of the titles that follow the last title found in the old NOVELS file. OUT.1 will become the replacement for NOVELS. It should only contain updated TG entries. In OUT.2, remove all of the titles up to and including the last title found in the old NOVELS file. This represents the list of titles that *may* not be in the old NOVELS file. After inspection (most likely a diff -h of the OUT.1 file with the target file), you may replace the old NOVELS file with OUT.1 
       	cp OUT2 OUT.1
	mv OUT2 OUT.2
	-- edit files --
  6. Some award titles will not match the titles in the regular database. That doesn't mean that the titles aren't present. This can be figured out by looking at all of the titles in OUT.2 and checking to see if any of the award tags there are present in NOVELS. Use awdiff to do this: 
       	../bin/awdiff ../dbase.ascii/NOVELS OUT.2 > OUT
    The output (OUT) consists solely of those records which do not have matching award tags in the NOVELS file. We don't care about the records that have matching award tags because they were obviously merged in a prior session. What remains will have to be hand merged.

Merging Forthcoming Books

  1. Make updates to the MS Access database. It is adviseable that the data be sorted by publication date to make removal of books that fall of the list at the beginning of a new month easy.

  2. Export the database to the file "forth.txt", using "|" as the field delimiter, and a text specifier of "{none}". This will output the Access database into a text file, using the pipe as the field delimiter.

  3. Move "forth.txt" to Linux, and place in the SFdbase/forthcoming directory. Edit the file and remove trailing ^M's, and append a "|". This makes the file parsable by the tools.

  4. In SFdbase/forthcoming, execute: 
    	make
    This will create new versions of the ANTHOLOGIES, COLLECTIONS, NONFICTION, NOVELS, and OMINBUS files in the forthcoming directory. Note that this requires utilizing the "Text Type" field, so it is critical that the field be set to one of: a, c, nf, n, o.

  5. Append the following files in SFdbase/forthcoming: 
    	ANTHOLOGIES
	COLLECTIONS
	NONFICTION
	NOVELS
	OMNIBUS
    to the same files in SFdbase/dbase.ascii, and the run the tools/merge command on each of the files.
  6. Run the SFdbase/tools/checkauthor tool on each of the modified files to check for bad author names.
  7. Copy the "forthcoming" file that was generated by make into SFdbase/forthcoming. Then execute: 
    		./updateforth
